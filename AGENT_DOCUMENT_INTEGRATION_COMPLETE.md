## 🔥 How It Works

### When Agent Takes a Turn:

1. **Agent speaks in debate** → Message saved as event
2. **Document check** → System looks for active document
3. **Section lookup** → Finds sections assigned to this agent
4. **Content generation** → LLM generates section-specific content:
   - **Text sections**: Summarizes agent's point for that section
   - **Diagram sections**: Generates Mermaid.js code
5. **Section update** → Updates `document_sections` table:
   - `word_count` tracked
   - `status` → 'in_progress' → 'completed'
   - Timestamps recorded
6. **Document completion** → When all sections done, document marked 'completed'

### Content Generation Strategy:

**For Text Sections:**
```
Prompt: "Write content for '{section_title}'
- Your role: {agent's system prompt}
- Based on: {agent's debate message}
- Limit: {word_limit} words
- Focus on specific aspect of {section_title}"
```

**For Diagram Sections:**
```
Prompt: "Generate Mermaid.js diagram for '{section_title}'
- Context: {debate topic}
- Based on: {agent's discussion point}
- Return only Mermaid code (flowchart/sequence/ER)"
```

## 🐛 Troubleshooting

### If agents don't write to document:
1. Check backend logs for "📄 DOCUMENT WRITING" messages
2. Verify document exists: `SELECT * FROM documents WHERE debate_id = '...'`
3. Verify sections assigned: `SELECT * FROM document_sections WHERE document_id = '...'`
4. Check agent has OpenRouter API key configured

### If document doesn't show in UI:
1. Verify document was created during setup
2. Check: `curl http://localhost:8000/debates/{debate_id}/document`
3. Ensure "Enable Document Collaboration" was toggled ON

### If diagrams don't render:
1. Check section type is 'diagram'
2. Verify Mermaid syntax in backend logs
3. Check browser console for Mermaid errors
4. Try refreshing the page
